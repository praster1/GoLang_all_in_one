# 01. 첫 Go 프로그램

| 난이도 | 선수 지식 | 실행 예제 |
| --- | --- | --- |
| 입문 | [00. 개발 환경 준비](../00-setup/README.md) | [hello/main.go](../../examples/01-first-program/hello/main.go) |

## 학습 목표

- `package`, `import`, `func main()`이 각각 맡은 역할을 설명한다.
- 코드의 출력 결과를 예측하고 실제 결과와 비교한다.
- `go run`과 `go build`를 목적에 맞게 사용한다.
- 에러 메시지에서 파일과 위치를 확인한다.

## 1. 가장 작은 출발점

프로그램은 컴퓨터가 수행할 동작을 코드로 표현한 것입니다. 이번 장에서는 터미널에 한 줄을 출력하는 프로그램을 읽습니다. 입력, 데이터베이스, 서버가 없어도 코드 작성부터 실행까지의 흐름을 경험할 수 있습니다.

다음은 저장소의 [실제 예제 파일](../../examples/01-first-program/hello/main.go)과 같은 코드입니다.

```go
package main

import "fmt"

func main() {
	fmt.Println("안녕하세요, Go!")
}
```

먼저 코드를 한 번 읽고, 무엇이 출력될지 예상해 보세요. 이후 저장소 루트에서 실행합니다.

```text
go run ./examples/01-first-program/hello
```

예상 출력:

```text
안녕하세요, Go!
```

명령 앞에 보이는 `$`, `PS>` 같은 터미널 프롬프트는 입력하지 않습니다. 이 교재의 명령 블록에는 직접 입력할 내용만 표시합니다.

## 2. 코드를 한 줄씩 읽기

### `package main`

`package`는 이 파일이 속한 패키지를 선언합니다. 패키지는 관련 Go 코드를 묶는 단위입니다. 실행 프로그램은 `main` 패키지에 진입점인 `main` 함수를 둡니다. 파일 이름이 `main.go`이기 때문에 실행되는 것이 아니라, 패키지와 함수 선언이 역할을 결정합니다. [Go 명세의 프로그램 실행 설명](https://go.dev/ref/spec#Program_execution)을 참고하세요.

처음에는 “실행할 예제 하나를 폴더 하나에 둔다”는 규칙을 기억하면 충분합니다. 같은 폴더에 여러 예제의 `func main()`을 모아 두면 중복 선언 문제가 생길 수 있습니다.

### `import "fmt"`

`import`는 다른 패키지의 기능을 사용하겠다는 선언입니다. `fmt`는 문자열 서식과 입출력을 제공하는 표준 라이브러리 패키지입니다. Go 설치에 포함되어 있으므로 이 예제 때문에 추가 패키지를 다운로드하지 않습니다. [fmt 공식 문서](https://pkg.go.dev/fmt)에서 제공 기능을 확인할 수 있습니다.

이 장의 코드에서는 `fmt.Println`을 호출하기 위해 `fmt`를 가져옵니다. 가져온 패키지를 사용하지 않으면 컴파일 오류가 발생합니다. 예를 들어 출력문을 지웠다면 필요 없어진 `import "fmt"`도 함께 정리해야 합니다.

### `func main() { ... }`

`func`는 함수를 선언합니다. 함수는 이름을 붙여 둔 동작의 묶음입니다. 이 함수의 이름은 `main`이며, `{`와 `}` 사이에 실행할 문장을 적습니다.

일반적인 실행 프로그램은 패키지 초기화가 끝나면 `main` 함수를 실행합니다. 이번 예제에서는 출력문 하나를 실행한 후 함수가 끝나고 프로그램도 종료됩니다. 함수의 입력과 반환값은 이후 장에서 자세히 다룹니다.

Go 코드에서는 여는 중괄호를 아래처럼 함수 선언과 같은 줄에 둡니다.

```go
func main() {
	// 실행할 문장
}
```

이 코드 조각은 함수의 모양만 설명합니다. 실행하려면 패키지 선언 등을 포함한 전체 파일이 필요합니다.

### `fmt.Println("안녕하세요, Go!")`

`fmt.Println`은 `fmt` 패키지의 `Println` 함수를 호출하는 표현입니다. 괄호 안의 값이 함수에 전달됩니다. 큰따옴표로 감싼 `"안녕하세요, Go!"`는 문자열입니다.

`Println`은 전달된 값을 표준 출력에 쓰고 끝에 줄바꿈을 붙입니다. 따라서 여러 번 호출하면 줄이 나뉩니다. 이 동작의 정의는 [fmt.Println 문서](https://pkg.go.dev/fmt#Println)에 있습니다.

| 코드 요소 | 이 예제에서의 의미 |
| --- | --- |
| `fmt` | 사용할 기능이 들어 있는 패키지 |
| `.` | 패키지의 이름과 그 안의 이름을 연결 |
| `Println` | 호출할 함수 |
| `("안녕하세요, Go!")` | 함수에 전달할 문자열 |

## 3. 읽기 → 예측 → 실행 → 설명

예제를 이해했는지 확인하는 방법은 그대로 따라 치는 것에서 한 단계 더 나아가는 것입니다.

다음은 **출력문을 바꾸는 연습용 코드 조각**입니다.

```go
fmt.Println("Go를 공부합니다.")
fmt.Println("오늘은 첫 번째 프로그램입니다.")
```

실행 전에 출력이 몇 줄인지 적어 봅니다. 두 문장을 `main` 함수 안에 넣어 실행하면 다음처럼 출력됩니다.

```text
Go를 공부합니다.
오늘은 첫 번째 프로그램입니다.
```

개인 실습은 [연습 폴더 만드는 방법](../../exercises/README.md)을 따라 `/_practice/` 아래에서 진행합니다. 교재의 기본 예제와 예상 출력은 그대로 두고, 자기 실습 파일을 자유롭게 바꿀 수 있습니다.

## 4. `go run`과 `go build`

`go run`은 코드를 빌드한 뒤 바로 실행하므로 학습 중 결과를 확인하기에 편리합니다. Go가 해석형 언어처럼 소스를 한 줄씩 그대로 실행한다는 뜻은 아닙니다.

`go build`는 실행 파일을 만들 때 사용합니다. 아래 명령은 저장소 루트에서 실행합니다. `bin/`은 생성물을 두는 폴더입니다.

### Windows PowerShell

```powershell
New-Item -ItemType Directory -Force bin | Out-Null
go build -o bin/hello.exe ./examples/01-first-program/hello
.\bin\hello.exe
```

### macOS·Linux·WSL

```bash
mkdir -p bin
go build -o bin/hello ./examples/01-first-program/hello
./bin/hello
```

두 경우 모두 실행했을 때 `안녕하세요, Go!`가 출력됩니다. 빌드 명령만 실행하면 인사말은 출력되지 않습니다. 생성한 실행 파일을 실행해야 합니다. 운영체제별 실행 파일은 별도로 빌드하므로 Windows에서 만든 `.exe` 파일을 Linux용 예제로 생각하지 않습니다.

세부 옵션은 [go run](https://pkg.go.dev/cmd/go#hdr-Compile_and_run_Go_program)과 [go build](https://pkg.go.dev/cmd/go#hdr-Compile_packages_and_dependencies)의 공식 설명을 참고합니다.

## 5. 테스트로 예상 출력 확인하기

이 예제에는 예상 출력을 확인하는 테스트가 있습니다. 저장소 루트에서 다음을 실행합니다.

```text
go test -v ./examples/01-first-program/hello
```

여기서는 “이 프로그램이 약속한 인사말을 출력하는지 확인한다”는 목적만 이해하면 됩니다. 테스트 문법과 다양한 검증 방법은 이후 테스트 장에서 다룹니다. Go의 실행 가능한 예제 테스트는 [testing 공식 문서](https://pkg.go.dev/testing#hdr-Examples)에 설명되어 있습니다.

`ok`는 이 실행에서 포함된 테스트가 통과했다는 뜻입니다. 코드 전체에 결함이 없다는 보장은 아니므로, 테스트가 무엇을 확인하는지도 함께 읽는 습관을 들입니다.

## 6. 실수와 오류 읽기

오류를 연습할 때는 개인 실습 파일을 이용합니다. 한 번에 하나만 바꾸고, 어떤 메시지가 나왔는지 확인한 뒤 원래 의도대로 고칩니다.

| 실수 | 원인 | 확인할 점 |
| --- | --- | --- |
| `fmt.println(...)`으로 작성 | Go는 이름의 대소문자를 구분합니다. | `Println`의 첫 글자 `P`를 확인합니다. |
| `import "fmt"`를 빠뜨림 | 사용하는 패키지를 가져오지 않았습니다. | import 선언을 확인합니다. |
| `fmt`를 가져오고 사용하지 않음 | 사용하지 않는 import가 남았습니다. | 필요한 코드만 남깁니다. |
| 문자열을 닫는 `"`를 빠뜨림 | 문자열의 끝을 해석할 수 없습니다. | 따옴표 쌍을 확인합니다. |
| 같은 폴더에 `main` 함수 두 개를 둠 | 같은 패키지에서 이름이 중복됩니다. | 서로 다른 예제는 폴더를 나눕니다. |
| 저장소 루트에서 `go run .` 실행 | 루트에는 실행할 Go 파일이 없습니다. | 예제 패키지의 경로를 지정합니다. |

오류 메시지에는 보통 파일 이름과 줄·열 위치가 함께 나옵니다. 에러 문구 전체를 외우기보다 **어느 파일의 어느 위치에서 무엇을 해석하지 못했는지** 읽으세요. 정확한 문구는 Go 버전과 코드에 따라 달라질 수 있습니다.

## 8. 이해 확인

코드를 보지 않고 대답한 뒤 아래 답을 확인합니다.

1. 파일 이름을 `hello.go`로 바꾸면 `func main()`이 실행되지 않을까요?
2. `fmt.Println`을 두 번 호출하면 출력은 몇 줄일까요?
3. 실행 파일만 만들고 싶을 때는 어떤 명령을 사용할까요?
4. 예제 폴더마다 `go.mod`를 만들어야 할까요?

<details>
<summary>답과 설명</summary>

1. 실행됩니다. 진입점은 파일 이름이 아니라 `main` 패키지의 `main` 함수입니다.
2. 이 장처럼 줄바꿈이 포함되지 않은 문자열을 전달한다면 두 줄입니다. `Println`이 호출마다 끝에 줄바꿈을 붙입니다.
3. `go build`를 사용합니다. 만든 파일은 별도로 실행합니다.
4. 이 저장소는 루트 모듈 하나를 사용합니다. 예제 폴더에 별도 `go.mod`를 추가하지 않습니다.

</details>

## 정리

Go 실행 예제는 `main` 패키지와 `main` 함수에서 출발합니다. 필요한 기능은 `import`로 가져오고, `fmt.Println`으로 문자열을 출력했습니다. `go run`으로 빠르게 실행하거나 `go build`로 실행 파일을 만들 수 있습니다. 이제 코드를 조금 바꾸고, 결과를 예측하고, 실제 출력으로 확인하는 흐름을 반복해 보세요.
