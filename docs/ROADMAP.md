# 집필 로드맵과 완료 범위

전체 32장(00–31장)의 본문·실습·해설과 실행 코드를 제공합니다. 세부 학습 순서는 [교재 목차](../book/README.md), 수행한 검사와 환경은 [검증 기록](VALIDATION.md)을 기준으로 합니다.

## 상태의 의미

| 상태 | 의미 |
| --- | --- |
| 예정 | 주제와 목표를 정했으며 본문은 아직 없음 |
| 집필 중 | 본문 또는 실습을 작성 중이며 누락된 부분이 있음 |
| 초안 | 본문과 해당 실습 자료를 제공하며 추가 검토가 필요함 |
| 검토 완료 | 본문·예제·문제·해설을 제공하고 내용·실행·검사 범위를 기록함 |

검토 완료는 알려진 범위에서 학습 경로와 코드를 확인했다는 뜻입니다. 모든 입력·운영체제·실제 운영 환경에서 결함이 없다는 보증을 뜻하지 않습니다. 확인한 환경과 실행하지 않은 항목은 검증 기록에서 구분합니다.

## 집필 이력

2026-11-09에 00–04장을 순서대로 집필하고 검증하여 반영했습니다. 환경 준비, 첫 출력, 변수·계산, 조건·반복, 함수·스코프의 학습 경로를 만들었습니다.

같은 날 나머지 05–31장도 앞 장들과 같은 방식으로 상세 집필했습니다. 각 장은 목표와 선수 지식, 개념 설명, 실행 코드·예상 출력, 흔한 실수, 확인·변형·응용 문제, 힌트와 별도 해설, 공식 참고 자료를 연결합니다. 중단된 집필을 이어받아 미완성 자료를 채우고 전체 목차·상호 링크·의존성·자동 검사를 갱신했습니다.

### 1. 시작과 언어 기초

배열의 값 복사와 슬라이스의 공유 저장 공간을 구분하고, `append`의 반환값과 `copy`의 의미를 확인합니다. 맵에서는 존재 여부·빈도·그룹별 합계를 다룹니다. 문자열에서는 바이트·룬·화면에 보이는 문자 단위를 구분하며, 잘못된 UTF-8과 정상적인 대체 문자도 비교합니다.

각 장의 개인 실습은 `_practice/` 아래 별도 디렉터리에 둡니다. 예제와 개인 답안을 구분하고, 제공하는 준비 명령은 기존 풀이 파일을 보존합니다.

### 2. 프로그램 구조와 검증

포인터·구조체·메서드·인터페이스를 통해 값의 소유와 변경 책임을 설명합니다. 패키지에서는 공개 API와 의존 방향을 구분하며, 루트 단일 모듈 안에서 여러 패키지를 구성합니다.

오류는 원인과 위치를 보존해 전달하고, 자원은 정리 시점까지 관리합니다. 자동 테스트에서는 정상 결과뿐 아니라 경계값·오류 원인·원본 보존·출력 실패를 검증합니다. 제네릭은 타입 제약과 실제 공통화 필요성을 함께 검토하며, 저장소 기준인 Go 1.27의 언어 규칙에 맞춥니다.

### 3. 실제 입력과 작업 수명

작은 파일 전체 읽기와 스트림 처리를 구분하고, 마지막 읽기의 데이터·EOF·쓰기 실패·버퍼 정리를 설명합니다. CSV·JSON·시간·명령행에서 외부 입력을 검증하는 경계를 연습합니다.

동시성 예제에는 시작뿐 아니라 완료 대기, 전송·닫기의 책임, 취소 확인, 공유 상태 보호가 있습니다. 테스트는 시간 지연만으로 실행 순서를 가정하지 않고 채널·완료 신호와 경계 조건을 사용합니다.

### 4. HTTP·SQL·운영 기초

클라이언트의 상태 코드·본문 수명·제한 시간, 서버의 경로·메서드·JSON 응답, 핸들러 계약과 오류 경로를 단계적으로 검증합니다. HTTP 테스트는 `httptest`를 사용하고 개인 계정·외부 API를 요구하지 않습니다.

24장과 30장은 `modernc.org/sqlite`를 사용해 실제 SQL을 실행합니다. 메모리 또는 테스트 임시 파일의 DB를 사용하므로 별도 DB 서버가 필요하지 않습니다. 드라이버 버전과 간접 의존성은 `go.mod`·`go.sum`에 기록합니다. 설정, 구조화 로그, 비밀값의 경계와 정상 종료는 25장에서 연결합니다.

### 5. 측정·배포·완성 프로그램

성능 수치는 입력과 측정 환경에 따라 달라지므로 고정된 개선율을 정답으로 제시하지 않습니다. 벤치마크와 프로파일은 측정 절차와 해석을 가르치고, 퍼징은 불변 조건과 회귀 사례를 확인합니다.

배포 실습은 검사·빌드·대표 실행·체크섬과 산출물 보관까지 연결합니다. 실제 클라우드나 운영 서버의 배포·전환은 별도 환경의 정책이 필요하므로 기본 실습에서 다루지 않습니다.

## 이후 개정

요청된 00–31장의 집필 범위에 남은 예정 장은 없습니다. 독자 피드백을 바탕으로 오탈자, 설명의 빈틈과 재현된 결함을 수정합니다. Go 버전 또는 의존성을 올릴 때는 본문·예제·테스트·CI를 함께 확인합니다.

페이지 나누기 확장, 외부 인증 연동, 운영 DB별 특성, 부하 시험, 배치 체크포인트 등은 각 장의 선택 확장 또는 이후 개정 대상입니다. 이를 기본 과정의 미완료 항목과 혼동하지 않습니다.
